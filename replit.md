# iliOS - REA Investment Platform

## Overview
iliOS is a real estate asset investment management platform designed to manage the entire lifecycle of real estate investments, from acquisition and due diligence to asset management, financial tracking, and reporting. The platform aims to enhance decision-making through data-driven insights and improve operational efficiency for real estate investors and asset managers. Key capabilities include secure user authentication, multi-company user membership, a user-centric workspace, comprehensive asset and task management, financial oversight with budgeting and vendor management, sales pipeline tracking, and robust reporting tools. iliOS serves as a centralized system for investment oversight and operational governance for real estate professionals, with a vision to become the leading platform for data-driven real estate investment.

## System Architecture

### Frontend
- **Technology Stack**: React 18, TypeScript, Material UI (MUI), React Query, React Router DOM, AG Grid, Chart.js, Webpack 5.
- **UI/UX Decisions**: Standardized "Projects" terminology, robust navigation (Entity Context, Module Sidebar, Breadcrumb), a unified Context Bar for scope management, a static Asset Management Overview with drag-and-drop features, a collapsible sidebar, and consolidated admin/settings modules for improved user experience and access control.
- **Data Room Features**: Hybrid PDF/document viewer with programmatic page navigation, text search, and highlighting. Links AI-extracted fields to specific pages for evidence-based verification and provides an audit trail with a sequential verification workflow and bulk acceptance capabilities.
- **Project Summary Panel**: Collapsible panel within the Data Room providing cross-document analysis, including terms & values roll-up, co-terminus checks, and a project-level due diligence health indicator.

### Backend
- **Technology Stack**: Python 3.11, FastAPI, SQLAlchemy, Alembic, PostgreSQL.
- **Core Modules**: Workspace, Finance (capital governance, budgeting, vendor management), Acquisitions (13-stage deal pipeline), and Project Hub (unified asset management and due diligence).
- **Access Control**: Multi-Company Access System with granular authorization using a Canonical Effective-Access Resolver and Module-Level Permission Enforcement. Includes a Role Profiles System for detailed stakeholder definitions and a Portfolio Hub Boundary Model for data visibility, based on `read_only`, `contributor`, and `company_admin` roles.
- **Architectural Guardrails**: Asset Management Overview functions as a static record, linking to operational modules for live metrics.
- **Telemetry Module**: Project-scoped telemetry for Data Acquisition Systems (DAS) integration, health monitoring, and device mapping. Includes a **Demo Data Interceptor** (`DEMO_TELEMETRY=true` env var) that bypasses BigQuery with a solar bell-curve generator producing realistic 12-month production data. Demo data is seeded for site_id=1 with 10 inverters (INV-01..INV-10), 1 weather station (WS-01), 20 modules (MOD-01..MOD-20), a DAS connection, and full telemetry mappings. The interceptor patches `execute_bq_function` in `BaseTelemetryBigQuery` and the direct cumulative query methods in `TelemetrySiteBigQuery` and `TelemetryCompanyBigQuery`. Demo cleanup: remove `DEMO_TELEMETRY` env var, delete INV-*/WS-*/MOD-* devices, delete site mapping, delete DAS connection.
- **Company-Scoped Telemetry Providers**: `company_das_providers` association table (migration `ff14_company_das_providers`) tracks which DAS providers (KMC, Also Energy) are assigned to each company. API endpoints: `GET/POST /api/telemetry/companies/{company_id}/providers`, `DELETE /api/telemetry/companies/{company_id}/providers/{provider}` (Settings edit permission). Frontend ConnectionForm and TelemetryWizard fetch allowed providers per company; empty provider list shows informational message. Admin UI: `TelemetryProvidersSection` in Portfolio Admin Company Level page for assigning/removing providers. CRUD: `CompanyDASProviderCRUD` in `app/crud/company_das_provider.py`. Model: `CompanyDASProvider` in `app/models/telemetry.py`.
- **Document Versioning & Promotion System**: Manages lender-quality Data Room document versions with a "Promote to Current Assumptions" workflow, supporting `candidate`, `active`, and `retired` `ProjectFact` states with atomic transactions and diff computation.
- **Extraction Registry & Prompt Studio**: Scalable system for dynamic document type and field configuration using database-driven schemas and prompt templates, supporting re-extraction workflows.
- **In-App AI Parsing**: Fully in-app document parsing using Replit AI Integrations (OpenAI), featuring an `InAppParsingService` for file handling, text extraction, LLM calls via FastAPI BackgroundTasks, observability, and retry logic. Implements idempotency and concurrency safety with row locking and partial unique indexes. Quality guardrails enforce configurable settings for text length, file size, and LLM character limits.
- **Storage Service Abstraction**: Replit-native storage architecture with an abstract `StorageService` interface, supporting `ReplitStorageService`, optional `GCSStorageService`, and `HybridStorageService`.
- **Data Room Acceptance Safety**: Implements a parse run history panel for files and enforces acceptance safety rules, validating `run_id` and run status before allowing bulk acceptance of extracted data.
- **Contacts System**: A CRM-style contact management system for tracking external people related to portfolio, company, and project entities. Contacts are address book entries, not platform users, stored at three levels (portfolio, company, project) with exact-scope filtering and case-insensitive email uniqueness.
- **Finance Integration v1 (F1-F2)**: Company-level, read-only integration supporting multiple external providers with a pluggable architecture. Credentials are encrypted, and access is restricted to `company_admin` role with Finance module edit permission.
- **Finance Data Ingestion v1 (F3)**: Read-only data ingestion with normalized storage (`finance_accounts`, `finance_transactions`, `finance_sync_runs` tables). Sync runs use upsert semantics for idempotent reruns. Read endpoints (`GET /api/finance/accounts?company_id=`, `/transactions`, `/sync-runs`) require `finance:view`; sync trigger (`POST /api/finance/integrations/{company_id}/{provider_key}/sync`) requires `company_admin` + `finance:edit`. Provider stub data gated behind `use_stub_data` config flag, blocked in production unless `FINANCE_ALLOW_STUB_IN_PROD=true`. Observability via correlation IDs, structured logs, and stats tracking per sync run.
- **Company & Site Creation**: Company creation (`POST /api/companies/`) restricted to system users, requires structured address fields (address, city, state, county, zip_code) matching the Site model pattern. All company creation forms (onboarding, home dialog, portfolio admin, settings) include full address fields with US state dropdown and validation. Site creation (`POST /api/sites/`) uses `require_module_permission(assets_management:edit)` at company level. Alembic migration `ff11_company_address_fields` adds structured address columns to companies table.
- **Finance Health Indicators (F4)**: Company-level finance health summary via `GET /api/finance/summary?company_id=...` (requires `finance:view`). Returns `sync_status` (`not_configured`|`never_synced`|`running`|`healthy`|`error`), `last_sync_at`, `last_sync_error`, `accounts_count`, `transactions_count_30d`, `unmapped_projects_count` (placeholder), and `needs_attention_reasons` (machine-readable list). Health computation: `healthy` = last successful sync within 24h threshold; `error` = failed sync or stale sync or integration test failing; `running` = active sync in progress; `never_synced` = configured but no successful sync; `not_configured` = no integration exists. UI: `FinanceHealthCard` in Company Finance section (Portfolio Admin) with chip + secondary indicators + CTA for error state; `IntegrationHealthChip` in Project Hub Finance tab derived from company-level status.
- **Entity Directory System**: Portfolio-scoped directory of legal/business entities (EPC contractors, O&M providers, offtakers, tax equity, etc.) with project-level and deal-level role assignments. Three new tables: `project_entities` (directory), `entity_relationships` (project assignments with temporal tracking via effective/termination dates), `deal_entity_assignments` (deal-level references). Contacts table gains optional `entity_id` FK for entity-contact linking. Enums use snake_case values: `EntityType` (16 types), `EntityRelationshipRole` (15 roles), `DealEntityRole` (4 roles). API routes: `/api/entities/` (CRUD + `GET /api/entities/{id}/assignments`), `/api/projects/{site_id}/entity-relationships/` (project assignments), `/api/deals/{deal_id}/entity-assignments/` (deal assignments). Frontend: shared `EntityPicker` MUI Autocomplete component with inline create dialog used across 8 provider info cards, Ownership card (hold_co, project_co, tax_credit_fund), Compliance card (entity, bank), and Deal detail/creation forms. DD-sourced provider fields remain read-only. Legacy flat text columns on `site_additional_fields` left in place but unused. Migration: `ff12_entity_directory`.
- **Portfolio Admin Entity Directory**: Dedicated admin page under Portfolio Admin for centralized entity management. Added as "Entity Directory" tab (Tab index 1) in `PortfolioLevelPage.tsx` between Companies (Tab 0) and Portfolio Members (Tab 2, system admin only). Components: `EntityDirectoryTab` (searchable/filterable MUI table with debounced search, entity type filter dropdown, active/inactive toggle, loading skeletons, empty states, deactivate confirmation dialog, reactivate action); `EntityFormDialog` (MUI Dialog for create/edit with all entity fields including US state dropdown, email validation, and read-only project assignments panel fetched from `GET /api/entities/{id}/assignments`). `ProjectEntityUpdate` schema includes `is_active` field for deactivate/reactivate mutations. Files: `src/modules/portfolio-admin/components/entities/` (EntityDirectoryTab.tsx, EntityFormDialog.tsx, index.ts).
- **Home Dashboard "Your Projects" Widget**: `GET /api/workspace` response extended with `projects: List[WorkspaceProjectSchema]` containing project_id, project_name, company_id, company_name, address, city, state, system_size_ac, system_size_dc. Access-controlled: system users see all projects; company/portfolio members see all projects in their companies; project-only members see only their assigned projects. Frontend `HomeProjects` component in `src/modules/home/components/HomeProjects/` renders a card grid with project name, company chip, location, system size, and "Open Project" button navigating to `/project-hub/projects/{project_id}`. Registered in `widgetRegistry.ts` as full-width widget, included in `DEFAULT_VISIBLE_WIDGETS`.
