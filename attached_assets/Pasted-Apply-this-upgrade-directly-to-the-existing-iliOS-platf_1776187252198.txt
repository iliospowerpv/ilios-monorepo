-----------------------------------
IMPLEMENTATION REQUIREMENTS
-----------------------------------

ARCHIVE MODEL
For both Companies and Projects/Sites, add archive support with fields such as:
- isArchived: boolean default false
- archivedAt: datetime nullable
- archivedBy: user id nullable

Optional:
- archiveReason nullable

Do not hard delete records.

-----------------------------------
BACKEND / API
-----------------------------------

Create or update secure endpoints:

PATCH /companies/:id/archive
PATCH /companies/:id/restore
PATCH /projects/:id/archive
PATCH /projects/:id/restore

Requirements:
- validate record exists
- validate current user is admin
- return 403 for non-admins
- handle already archived / already restored states safely
- return clear JSON responses
- log archive and restore actions

Archiving behavior:
- set isArchived = true
- set archivedAt = current timestamp
- set archivedBy = current admin user id

Restore behavior:
- set isArchived = false
- clear archivedAt
- clear archivedBy or preserve in audit logs depending on architecture

-----------------------------------
AUTHORIZATION
-----------------------------------

Do NOT rely on frontend-only hiding.
Enforce admin permission on the server for:
- archive company
- restore company
- archive project/site
- restore project/site

If user is not admin:
- block action
- return 403
- show clean frontend error message

DATA INTEGRITY
-----------------------------------

For Company archive:

- archiving a company also archives all associated projects/sites

“Archiving this company will also archive all associated projects/sites. This can be undone by an admin.”

For Project/Site archive:
- preserve files
- preserve comments
- preserve activity history
- preserve analytics/history
- remove from active workflows and active lists only

FRONTEND
-----------------------------------

Update the existing UI so admins see:
- Archive Company button on company detail page
- Archive Project/Site button on project/site detail page

Non-admins should not see archive/restore controls.

Show confirmation modal.

Modal requirements:
Title:
- Archive Company?
- Archive Project?

- Related data will be preserved.
- This action can be undone by an admin.

Buttons:
- Cancel
- Confirm Archive

After successful archive:
- show success toast
- refresh or redirect cleanly

- Active

UNDO / RESTORE
-----------------------------------

Add two restore mechanisms:

1. Immediate undo option
- after archive, show toast/banner with Undo action if feasible

2. Permanent restore path
- archived records page or archived filter view

Restore should fully return the record to active state.

If restoring a company, restore child projects/sites if they were archived as part of that company archive flow.

EDGE CASES
