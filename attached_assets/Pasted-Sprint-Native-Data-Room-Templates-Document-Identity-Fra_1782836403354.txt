Sprint: Native Data Room Templates & Document Identity Framework (Architecture + Foundation)
Status
Architecture + implementation.

This sprint may introduce additive schema, services, UI, and APIs.

It may NOT replace the existing Data Room.

Everything must extend the current native implementation.

Primary Objective
Transform the existing Data Room into a guided, template-driven system that preserves the existing document lifecycle while preventing duplicate logical documents.

The current problem is that users create multiple logical copies of the same document simply because filenames differ.

Example:

PVsyst
PVsyst Final
PVsyst Post Permit
PVsyst Updated
These should instead become

Document Identity:
PVsyst

Versions:
• Initial
• Final
• Post Permit
• Revision 3
The existing version management already supports this.

Users simply are not being guided correctly.

The system should guide them rather than allowing accidental duplication.

Permanent Architectural Rules
These are architectural invariants.

Rule 1
The existing Data Room remains the system of record.

Do NOT create another document management system.

Rule 2
Do NOT create a new top-level module.

Everything belongs inside the existing Data Room.

Rule 3
Templates define expected structure.

They never own documents.

Rule 4
Every uploaded file belongs to exactly ONE logical Document Identity.

Never duplicate business objects simply because filenames differ.

Rule 5
The existing document page remains the owner of

version history

promotions

archive

delete

metadata

approvals

Nothing duplicates this functionality.

Rule 6
Every new workflow must wrap existing native functionality.

No parallel upload path.

No parallel archive path.

No parallel promotion path.

No second execution path.

Rule 7
The AI Assistant never performs uploads, promotions, archive operations, deletes, or moves.

It only guides users into existing workflows.

Success Criteria
At the end of this sprint:

A new project can be created from a reusable Data Room template.

Users are guided toward adding new versions instead of duplicate documents.

The existing document lifecycle (versions, promotion, archive, delete, move) remains the single source of truth.

The AI Assistant can explain template structure, missing documents, and document status, while remaining strictly advisory and never creating a second execution path.

The architecture is positioned for future AI-guided due diligence without introducing duplicate document-management logic.
