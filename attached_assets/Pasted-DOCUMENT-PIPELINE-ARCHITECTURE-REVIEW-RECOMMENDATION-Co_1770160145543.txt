DOCUMENT PIPELINE ARCHITECTURE REVIEW & RECOMMENDATION

Context:
This is a fresh install and new deployment of the Ilios platform. There are no legacy users or production data. We are willing to refactor significantly, but we must preserve existing, working functionality where it already aligns with the intended architecture.

The current system includes:
- A Data Room used for document upload and management
- AI-based document parsing and extraction
- Extraction previews shown to users
- Extracted fields stored as DocumentKeys
- An acceptance/override workflow where approved fields become canonical project data and flow into other modules (Finance, O&M, Reporting)

We are experiencing instability and confusion due to:
- Multiple cloud projects
- Mismatched secrets
- Unclear boundaries between storage, parsing, and AI extraction
- Difficulty reasoning about which services are authoritative

We want to rebuild this *properly* going forward, not just patch it.

IMPORTANT CONSTRAINTS
- This runs in Replit and should work well with Replit’s embedded services and deployment model.
- We are NOT constrained by migration or backward compatibility.
- We DO care deeply about:
  - Reliability
  - Extensibility to new document types
  - Clear data lineage from document → extracted field → accepted canonical value
- We do NOT want to break:
  - Data Room UX
  - Document upload flows
  - Extraction preview + acceptance workflow
  - Downstream usage of accepted fields in other modules
