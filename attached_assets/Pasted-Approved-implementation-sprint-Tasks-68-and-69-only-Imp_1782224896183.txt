TASK #69 — V2 Performance Context Read Model

Objective:
Create a new additive, read-only canonical V2 Performance Context read model. This is a backend service + endpoint only. No frontend consumers migrate in this task.

Future consumers only:
- Performance Context panel
- Project Hub summaries
- Investor Performance Reports
- O&M dashboard consumers

Critical constraints:
- Read-only composition only.
- No writes.
- No ingestion.
- No activation/promote/revalidate behavior.
- No expected math changes.
- No baseline selection changes.
- No weather declaration/governance changes.
- No WS.5 work.
- No BigQuery, Firestore, SAFL, or legacy telemetry as operational truth.
- Do not alter existing O&M chart endpoints.
- Do not alter existing V2 series endpoints.
- Do not migrate any current consumer.

Architecture sequence:
1. Build independently testable Performance Context service/helper first.
2. Add unit/integration tests.
3. Validate Site 4.
4. Only then expose the endpoint.

Endpoint:
GET /api/telemetry/v2/sites/{site_id}/performance-context

Response must include:
schema_version: "1.0"

The response must include a canonical envelope with:
- per-bucket series
- nullable actual_kw and/or actual_kwh
- nullable expected_kw and/or expected_kwh
- variance and variance_percent only when mathematically valid
- actual_state
- expected_state
- baseline_state
- observed irradiance
- observed temperature
- weather semantic state
- weather expected-model eligibility
- telemetry freshness/completeness
- source provenance
- UTC bucket timestamp
- site-local display timestamp
- bucket timezone metadata
- window summary

Actual rules:
- measured zero = 0
- unavailable = null
- negative tare/parasitic values preserved
- never fabricate zero
- never infer outage from missing telemetry

Expected rules:
- Use expected_service verbatim.
- No formula change.
- No baseline change.
- Expected unavailable must be explicit via expected_state, never fabricated.

Variance rules:
Calculate variance only when:
- actual exists
- expected exists
- expected > 0

Otherwise:
variance = null
variance_percent = null

Actual-state taxonomy:
Support at minimum:
- available
- partial
- telemetry_unavailable
- telemetry_stale
- no_production_during_interval
- pre_pto
- insufficient_data
- not_applicable

Weather rules:
- Project existing weather semantics verbatim from existing services.
- Do not derive or reinterpret weather semantics in the aggregator.
- used_by_active_model must remain false until WS.5 exists.
- Use only contextual labels unless governed declarations already support stronger labels.
- No POA label unless governed declaration supports it.
- No cell/module temperature label unless governed declaration supports it.
- No causal/root-cause language.

Provenance:
Each bucket must support:
- source_provenance
- telemetry_freshness
- telemetry_completeness
- timezone
- utc_timestamp
- site_local_display

Never fabricate provenance. If absent, use null.

Timezone:
- UTC remains canonical.
- Site timezone affects daily/today boundary only.
- Bucket keys remain UTC.

Snapshot fixtures:
Produce JSON snapshots for:
1. Site 4
2. healthy site
3. no-baseline site
4. stale telemetry site

Tests:
Add tests for:
- missing actual → null + actual_state, never 0
- genuine 0 preserved
- negative preserved
- expected states preserved
- variance null when either side missing
- variance percent null when expected <= 0
- weather semantics copied verbatim
- provenance copied or null, never fabricated
- timezone correctness
- auth/cross-tenant behavior
- zero writes
