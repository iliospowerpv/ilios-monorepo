You are working on the Ilios application.

Your task is to design, build, populate, and permanently maintain a full in-app Help & Resources / FAQ / Documentation system for Ilios, similar in quality and usefulness to a mature SaaS knowledge base.

This is not a placeholder page. It must become a real product surface with user-facing documentation, FAQs, walkthroughs, module explainers, and technical guidance.

IMPORTANT GOVERNING RULE:
From this point forward, documentation is a required part of feature completion in Ilios.
For every new module, page, workflow, command, report, dashboard, data model, integration, or user-visible behavior you create or modify, you must also create or update the corresponding Help / FAQ / explainer content and ensure it appears in the Help & Resources system.
This is a hard requirement, not optional.
No feature is considered complete unless its documentation and help coverage are also created or updated.

Treat this as an enforced product rule going forward:
- Every new feature must have associated help documentation
- Every changed workflow must have updated documentation
- Every renamed field, button, page, metric, or navigation item must have updated documentation
- Every new report/dashboard must have “how to use” and “what it means” guidance
- Every complex metric or financial/operational term must have an explainer
- Every admin setting or system behavior must have reference documentation where relevant
- Every module should be represented in Help & Resources if user-facing
- When code changes affect product behavior, help content must be updated in the same task / same PR / same command execution if possible

Build this so future development naturally enforces and supports that rule.
