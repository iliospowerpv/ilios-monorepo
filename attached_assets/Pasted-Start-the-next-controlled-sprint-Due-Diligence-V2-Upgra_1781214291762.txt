Start the next controlled sprint: Due Diligence V2 Upgrade — Auditability, Document-Type Parsing Coverage, and Source-Backed Project Facts.

Strategic context:
The V2 telemetry and expected-performance foundation is now established:

* PostgreSQL V2 actuals
* V2 expected baseline storage
* V2 weather-adjusted expected calculation
* expected_state-driven UI behavior
* company/investor/portfolio V2 aggregation
* health/readiness V2-only
* legacy telemetry gated behind off-by-default legacy_telemetry_enabled

Now we need to upgrade the due diligence and AI parsing workflow so it becomes the controlled source of project truth and baseline-driving assumptions.

Core product principles:

1. AI-parsed data is not truth.
2. Accepted document terms are not automatically active project truth.
3. Promoted project_facts represent current approved assumptions.
4. Contracted/design/baseline facts must remain source-backed and auditable.
5. Baseline-driving assumptions should not be changed through casual manual override.
6. New or changed baseline-driving assumptions should require a new uploaded document or a formal audited review record.
7. Historical facts and baselines must not be overwritten.
8. Changes must support effective dates, supersession, and audit history.
9. A site may be upgraded, repowered, expanded, or have a second-phase buildout; this must create new effective facts/baselines, not rewrite history.
10. Every due diligence document type should be eligible for AI-assisted parsing through the extraction registry, even if some schemas start minimal.
11. Do not re-enable BigQuery, Firestore, ilios-DocAI, or legacy telemetry paths.
12. Do not auto-promote AI output.
13. Do not auto-activate expected baselines.

Target workflow:
Document upload
→ document type classification / selection
→ AI parse using document-specific schema
→ extracted candidate terms/facts with evidence
→ human review
→ accepted / rejected / overridden terms
→ promotion into source-backed project_facts
→ downstream action depending on fact type:

* create expected baseline draft
* update legal/commercial assumptions
* update equipment schedule
* update warranty/permit/insurance data
* flag discrepancy against telemetry-discovered devices
* create follow-up task / missing-data item
  → separate approval/activation where required
  → immutable audit history

Scope for this sprint:
Implement Phase 1 only: provenance/audit strengthening and document-type parsing coverage foundation.

Do not build the full baseline draft bridge yet. Do not remove legacy DD → BigQuery write yet unless it is already fully gated and safe. Do not change baseline calculation logic.

Use existing fields where they already exist. Add only what is necessary and additive.

Requirements:

* No existing due diligence records should break if provenance fields are null.
* Existing promotion behavior must continue to work.
* Existing candidate/active/retired fact behavior must continue to work.
* Do not overwrite historical facts.
* Promotion should retire/supersede prior active facts rather than mutate them.
* If a value is overridden by a human reviewer, retain both the AI-extracted value and the human-approved value if the current model supports it; otherwise propose the smallest additive change to support it.
* Evidence should remain linked back to the source document wherever possible.
