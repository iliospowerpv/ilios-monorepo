Start audit sprint: V2 Actual Production Curve Integrity — Telemetry to O&M Chart Trace.

This is an audit-only sprint. Do not implement code, migrations, endpoint changes, UI changes, data repairs, rollup backfills, or provider sync changes unless a follow-up implementation sprint is approved.

Context:
Site 4 now has an active corrected weather-adjusted baseline and expected values can compute. However, O&M actual production appears as an implausibly flat line. A solar generation series should vary by interval and fall to zero overnight.

This raises concern that actual telemetry is being incorrectly ingested, normalized, rolled up, selected, transformed, time-bucketed, or rendered.

Strategic objective:
Trace Site 4 actual-production data end-to-end and determine exactly where the flat-line behavior originates.

Hard constraints:

* Do not alter raw telemetry readings.
* Do not alter telemetry rollups.
* Do not run backfills.
* Do not change provider credentials.
* Do not change telemetry ingestion.
* Do not change expected formula math.
* Do not change WeatherResolver.
* Do not change baseline physics validation.
* Do not change baseline lifecycle.
* Do not mutate project_facts or accepted values.
* Do not use BigQuery, Firestore, or legacy telemetry as an operational fallback.
* Do not fabricate missing telemetry.
* Preserve genuine zero values.
* Preserve null as null; do not convert missing actuals to zero.
* Preserve timezone semantics and document every conversion.

Durable telemetry invariant:
Actual production shown in Ilios must be traceable to V2 raw readings and V2 rollups, with metric semantics, interval boundaries, units, timezone, and aggregation method explicitly identified.

E. Metric-semantic audit

Determine which metric is intended for the O&M actual curve:

* instantaneous AC power
* interval average AC power
* interval energy
* cumulative lifetime energy
* daily energy

For each candidate metric currently available:

* provider source metric
* V2 normalized metric
* unit
* monotonic versus variable behavior
* correct aggregation rule
* correct chart usage
* whether it is being used correctly today

Explicitly determine whether a cumulative-energy metric is being incorrectly rendered as power or copied across buckets.

F. Timezone / daylight audit

Audit timezone handling end-to-end:

* provider timestamp timezone
* raw reading timezone
* database storage timezone
* rollup bucket timezone
* site timezone
* frontend request timezone
* frontend display timezone

Test a daylight window and overnight window.

Answer:

* Are local overnight periods represented correctly?
* Is UTC-to-local conversion shifting data into wrong hours?
* Are buckets being grouped by UTC date instead of site-local date?
* Does DST affect the chart path?

G. Chart transformation audit

Trace all frontend and backend transforms from rollup response to rendered points.

Specifically check for:

* `|| 0` or null-to-zero coercion
* forward fill / last observation carried forward
* fallback to latest actual value
* map/reduce grouping that uses one value for all timestamps
* chart labels disconnected from value timestamps
* merge/join errors between actual and expected series
* use of daily aggregates for hourly labels
* repeated object references or stale cached arrays
* incorrect memoization keys
* date-range/cache invalidation issue after baseline activation

H. Expected versus actual separation

Confirm:

* actual series comes from V2 telemetry rollups only
* expected series comes from period-effective baseline computation only
* actual does not inherit expected values
* expected does not overwrite actual values
* chart merge preserves nulls and genuine zeroes independently

I. Root-cause classification

Classify the flat-line origin as exactly one or more of:

1. provider data issue
2. raw ingestion issue
3. normalized-reading issue
4. rollup aggregation issue
5. metric-semantic mismatch
6. timezone/bucket issue
7. backend chart-builder issue
8. frontend transformation/rendering issue
9. cache/query invalidation issue
10. unknown / needs more data

For every confirmed root cause:

* exact file/service/query/component
* evidence
* severity
* user-facing impact
* recommended repair
* whether historical backfill would eventually be needed
* whether repair is read-only, data repair, or code change
