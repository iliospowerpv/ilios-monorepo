You are the Replit agent in the Ilios codebase. ====================================================
CORE DEFINITIONS (NON-NEGOTIABLE)
====================================================
1) “Portfolio” in the UI is the logged-in user’s accessible portfolio:
   - Only companies/projects they created or were granted access to.
   - Never “all companies in the database.”
2) “Portfolio access” must be scoped to a portfolio boundary (hub), not global.
3) Portfolio boundary is represented by a portfolio hub company:
   - companies.portfolio_hub_id defines grouping.

====================================================
PART 0 — DO NOT DO
====================================================
- Do NOT keep global portfolio access behavior.
- Do NOT allow any API or UI route labeled “Portfolio” to return all companies unless user is_system_user and explicitly requests global admin view.
- Do NOT implement telemetry portfolio-shared connections until boundary exists.

====================================================
PART A — SCHEMA: PORTFOLIO HUB BOUNDARY
====================================================
1) Add column to companies (Alembic migration):
   - portfolio_hub_id INTEGER NULL REFERENCES companies(id)

Semantics:
- If portfolio_hub_id is NULL, the company is its own hub (implicit hub = company.id).
- If portfolio_hub_id is set, the company belongs to that hub company.

2) Add indexes:
- companies(portfolio_hub_id)

3) Add helper:
- resolve_company_hub_id(company): returns company.portfolio_hub_id or company.id

====================================================
PART B — SCHEMA: PORTFOLIO ACCESS MUST BE HUB-SCOPED
====================================================
1) Modify user_portfolio_access model to be scoped:
   - Add portfolio_hub_company_id INTEGER NOT NULL REFERENCES companies(id)
   - Add UNIQUE(user_id, portfolio_hub_company_id)

If a user should have access to multiple portfolios, they can have multiple rows.

2) Migration/backfill:
- Current data may have global portfolio members.
- Convert existing UserPortfolioAccess rows into hub-scoped rows:
  Strategy:
   - If there is a “primary/root” company concept today, map to that hub.
   - If not possible to infer, create a safe default:
       * For system users: allow global admin capabilities via is_system_user only.
       * For non-system users: require explicit assignment (set status to invited or suspended) and provide admin tool to assign hub.
  Document the chosen backfill approach and make it safe (no accidental global access).

====================================================
PART C — ACCESS RESOLUTION UPDATE (CRITICAL)
====================================================
Update access resolution so portfolio membership is limited to a hub group.

   all_companies = query(Company).all()
when portfolio access is present.

Instead:

   hubs = user_portfolio_access where status=active
