Start a read-only audit sprint: Project Hub Overview V2 Data Alignment Audit.

Do not implement code, migrations, route changes, UI changes, data-model changes, or refactors in this sprint.

Context:
The O&M / Device-Detail Drill-Down V2 Rebinding sprint is complete:

* Project Hub Devices grid now has category filters, V2 liveness/eligibility chips, and safe CSV export
* Project Hub Device Details now has a V2 actual-only performance card and Alerts tab
* old orphaned O&M device route was not relinked

Previous concern:
The Project Hub Overview page appears to read old data models. It may still rely on SiteAdditionalFieldList, legacy project summary fields, old due diligence characteristics, or old assumptions. We need to audit it before changing anything.

Objective:
Audit the existing Project Hub Overview tab and all related information cards to determine which fields are V2-native, which are legacy/display-only, which should be rebound to project_facts or V2 telemetry/baseline data, and which should remain as ordinary site metadata.

  * current Overview layout
  * information cards
  * draggable layout if present
  * MUI cards/tables/chips
  * existing typography/spacing/theme

C. Field classification

Classify every Overview field into one of these categories:

1. Ordinary site metadata
   Examples:

* site name
* address
* county/state
* coordinates
* ownership entity
* lender
* operator
* interconnection info
* ordinary administrative metadata

2. Lifecycle/construction metadata
   Examples:

* NTP
* LNTP
* mechanical completion
* PTO
* construction stage
* pipeline stage
* commercial operation date

3. Project assumption / diligence-derived fact
   Examples:

* system size DC/AC
* module type/count/wattage
* inverter type/count/wattage
* degradation
* losses
* soiling
* CEC efficiency
* contractual production
* PVsyst/design production

4. Telemetry/baseline-derived operational value
   Examples:

* actual production
* expected production
* weather-adjusted expected
* active baseline status
* design estimate points
* telemetry readiness
* device readiness

5. Legacy/display-only field
   Examples:

* old SAFL values that are not yet replaced
* old project summary fields
* old diligence characteristics

D. V2 source recommendation

For each field:

* current source
* recommended source
* whether change is required now, later, or not at all
* whether project_facts should become source of truth
* whether telemetry/baseline should become source of truth
* whether existing site metadata should remain source of truth
* whether SAFL should remain display-only temporarily
* whether a reconciliation indicator is needed

Rules:

* Baseline-driving assumptions should come from promoted project_facts, not SAFL.
* Operational values should come from V2 telemetry/baselines, not old summaries.
* Ordinary administrative metadata can remain in the existing site/entity models.
* Lifecycle fields may remain in site/deal metadata unless they are also baseline-driving assumptions, in which case reconciliation must show the distinction.
* Do not collapse design estimate, weather-adjusted expected, and actual production.
