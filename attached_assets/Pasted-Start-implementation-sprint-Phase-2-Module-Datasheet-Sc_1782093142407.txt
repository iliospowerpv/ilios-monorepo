Scope B — Equipment-aware extraction prompt

Replace the generic contractual prompt only for the new `module_specs` schema version.

The prompt must clearly state:

* This is a photovoltaic module datasheet, not a contract.
* Extract electrical, thermal, mechanical, and warranty specifications only when explicitly stated.
* Do not extract counterparties, governing law, fees, or contractual terms unless they are genuinely present and relevant to an explicitly requested field.
* Return raw value and raw unit separately.
* Capture page, table/section, and concise source snippet for every extracted value.
* Return `not_found` when absent.
* Return `unclear` when present but ambiguous.
* Never estimate or infer values.
* Never select one module variant from a multi-SKU datasheet.
* When a document lists ranges or multiple wattage variants:

  * return the candidate range/variants;
  * identify the ambiguity;
  * require reviewer selection or override;
  * do not populate a single installed value automatically.

Temperature-specific requirements:

* Thermal coefficient must identify the metric basis, such as Pmax, Voc, or Isc.
* Only Pmax/power coefficient may map to `thermal_coefficient_pct`.
* Preserve whether the source unit is `%/°C` or `%/°F`.
* Do not convert the basis automatically.
* Missing coefficient basis must be `unclear`, not normalized.

Tolerance-specific requirements:

* Preserve sign and whether the source expresses a range.
* Do not infer a minimum tolerance from a one-sided positive maximum.
* A source such as `0 to +5%` must not automatically populate `power_tolerance_min_pct` as zero unless reviewer confirmation explicitly chooses that interpretation.

Degradation-specific requirements:

* Extract only when explicitly stated.
* Do not derive year-one or annual degradation from broad warranty language in this sprint.
* Preserve exact warranty wording and source evidence.

Scope E — Unit behavior

Implement only the minimum additive unit metadata necessary for Module Datasheet review.

Required behavior:

* W and Wp may be displayed as raw source units.
* A normalized W candidate may be suggested only with explicit reviewer confirmation.
* kW/kWp conversion may be suggested but never applied automatically.
* `%` may be safely stripped only as a candidate suggestion.
* `%/°C` versus `%/°F` is always reviewer-confirmed.
* Bare numeric values without unit are ambiguous.
* Preserve raw unit, normalized candidate unit, normalization method, and confirmation state where the current model can support it additively.
* Do not migrate or mutate old document_keys/project_facts in place.
